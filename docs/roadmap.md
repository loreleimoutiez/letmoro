# Delivery plan

## 1. Foundation

Record agreed requirements, establish English conventions, isolate the domain engine, and implement a clearly labeled simulated-step prologue. Verify deterministic progression, first wages, personal choices, save handling, keyboard access, reduced motion, and clock-based themes.

## 2. Resolve rule boundaries

- Settle goal changes, travel pricing, reserve changes, and daily bonus caps.
- Define calendar boundaries, time-zone changes, incomplete days, synchronization delays, and late step corrections.
- Define mode-switch accounting, weekly resets, free-mode life display, and emergency-pause activation.
- Define the rescue day, when the player accepts it, unused rescue rights on voluntary reboot, and failure resolution.
- Define automation budgets, allowed risks, and when journey authorization resets.
- Choose starting languages, translation review, account method, privacy policy, export/deletion, hosting, and license.

Ask focused questions when a decision blocks implementation; do not reopen settled creative choices.

## 3. Hardware proof

Test S23 + Fit3 step export, Health Connect permissions and aggregation, delayed and corrected records, offline behavior, and application resumption. Establish whether cadence challenges are viable. No health-based life loss until these rules and data guarantees are verified.

## 4. Complete narrative design

Write the act structure and cast before expanding the world. Produce a representative first act, then review pacing for different personal goals. Track branch reachability and content depth. Author all major routes, romances, personal projects, delayed consequences, and conclusions before the first public campaign release.

## 5. Production readiness

Build resilient versioned persistence, account synchronization, migrations and backups; validate accessibility, languages, Android packaging, data permissions, content updates, and failure recovery. Implement CI when a working dependency lockfile is available. Publish accurate setup instructions and licensing before GitHub release.

## Implementation checkpoint — 2026-11-05

The internal simulated prologue, versioned local save format, deterministic progression tests, and clock-based theme are implemented. Type checking, six behavioral tests, and the production build pass. Browser verification remains blocked by sandbox socket restrictions; Git initialization and commits are blocked by read-only `.git`. See the handoff for exact limitations. The full first campaign and Android/health stages remain ahead.
